# BCHM scenario report source crosswalk

This workflow implements the user-visible input/save/report/sample affordances
that can be supported from cached evidence, while keeping the Python file
formats explicit where the native contract is unavailable.

| Workflow element | Evidence | Python behavior and boundary |
| --- | --- | --- |
| Named subgroup inputs | Cached `BCHM_HelpFile.pdf` identifies `nDat`, `xDat`, model inputs and seed; cached `BCHM_src/R/BCHM.R` returns subgroup results. | `BCHMScenario` captures subgroup labels, integer successes/trials, complete fit settings and seed. Names and CSV field layout are Python-defined because the native page exposes no upload schema. |
| Input upload/save affordance | Cached `app.html` contains the CSV upload and “Save Input into a csv file” controls, and links `BCHM_InputTemplate.zip`. | `from_input_csv` and `write_input_csv` round-trip the documented Python schema. No claim of native template compatibility. |
| Analysis | Cached `BCHM_src/R/BCHM.R` calls clustering then target-specific borrowing; existing Python `bchm_fit` implements the two stages. | Batch workflow calls `bchm_fit` unchanged for each scenario and records the root seed plus the exact cluster/target seeds generated by its NumPy seed sequence. |
| Analysis report | Cached `app.html` advertises PDF report download. PDF contents and server rendering code are not cached. | `report()` / `write_report()` produce a plain-text Python report with full declared design, results, diagnostics and implementation differences. PDF parity is not claimed. |
| MCMC sample download | Cached `app.html` advertises sample download; no server export schema is present. Native package docs say samples are posterior response rates for all subgroups. | `write_samples_csv()` streams the existing retained target probabilities to a documented long-form CSV (`scenario`, `subgroup`, target/chain/draw indices, probability). It does not fabricate native chain or column conventions. |
| Monte Carlo error and diagnostics | Native R extracts the first JAGS chain; existing Python summaries calculate classical split R-hat and batch-means MCSE over requested chains. | Report reuses those posterior mean diagnostics and computes chain-aware summaries on exact logit-scale efficacy indicators. Similarity MCSE uses sequential batch means on allocation indicators. Estimates are diagnostics, not convergence guarantees. |
| Native parity | `docs/bchm-sources.json` records cached versions and hashes. The cached HTML does not expose handlers, PDF bytes or sample CSV output. | Exact native I/O contract and end-to-end Shiny/JAGS output parity remain open. Python uses NumPy streams and requested chains, unlike native R/JAGS behavior. |

Evidence was read from the task's existing cache at
`mdanderson-stats/research/raw/BCHM/`: `app.html`, `BCHM_HelpFile.txt`, and
`BCHM_src/R/BCHM.R`. Hashes and source versions are recorded in
[`docs/bchm-sources.json`](../docs/bchm-sources.json). No live application
request was made.
