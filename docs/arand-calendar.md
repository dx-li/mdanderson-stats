# Adaptive Randomization: calendar replay

`arand_calendar_replay` connects the [validated ARAND posterior models](arand.md)
to patient arrivals, delayed outcomes, allocation, interim monitoring and final
selection. It supports binary outcomes and exponential event times for one to
ten independent arms.

The version 5.2 guide specifies the posterior models and broad rules, but leaves
several controller choices open. The required `ArandControllerPolicy` makes
those choices explicit. This is a source-informed Python workflow; it is not
verified native-engine parity. Entry 62 remains partial.

## Binary trial with delayed observations

An arrival tape contains potential candidates, including candidates who might
be blocked by suspension or a trial limit. Outcome and delay matrices have one
row per candidate and one column per arm. Only the outcome for the arm actually
assigned to a candidate can become observed.

```python
import numpy as np
from mdanderson_stats import ArandControllerPolicy, arand_calendar_replay

policy = ArandControllerPolicy(
    floor_transform="mixture",
    ranking_scope="all_arms",
    trigger_order=("futility", "suspension", "early_winner"),
    duration_minimum_precedence="duration_wins",
    multiple_winner="highest_probability",
    all_suspended_action="skip_arrivals_until_next_analysis",
    same_time_order="analysis_before_arrival",
)
trial = arand_calendar_replay(
    arrival_times=np.arange(6, dtype=float),
    assignment_uniforms=[0.05, 0.95, 0.05, 0.95, 0.05, 0.95],
    prior=[[1, 1], [1, 1]], family="binary",
    binary_outcomes=np.tile([1, 0], (6, 1)), binary_window=1,
    analysis_times=[0.5, 2.5], max_enrollment=6, max_duration=None,
    final_followup=2, minimum_enrollment=2,
    initial_equal_randomization=2, minimum_allocation=0.1,
    final_winner_cutoff=0.95, policy=policy,
)
np.testing.assert_array_equal(trial.assignments, [0, 1, 0, 1, 0, 1])
# The final independent posteriors are Beta(4,1) and Beta(1,4).
np.testing.assert_allclose(
    trial.looks[-1].posterior_probability, [69/70, 1/70], atol=1e-10,
)
assert trial.final_winner == 0
assert trial.decision_duration == 5
assert trial.final_analysis_time == trial.completed_duration == 7
```

The uniforms make this example reproducible; they are not random numbers
generated by the replay. To evaluate a different data-generating process,
supply new arrival, uniform and potential-outcome tapes. The optional
`data_seed` records caller provenance only; it does not generate or alter data.

`binary_window` holds every assigned outcome until that elapsed time. To supply
candidate- and arm-specific availability times, replace it with a
`binary_delays` matrix. An early known response is usable only if its supplied
delay says it is available. All times use one caller-chosen unit.

## Exponential outcomes and censoring

`event_times` contains elapsed times from enrollment to the event. Positive
infinity means no event during finite follow-up. At each analysis, every
enrolled patient contributes observed time at risk, ending at the event if it
has occurred. The final analysis administratively censors patients still at
risk. `parameter="mean"` uses inverse-gamma shape/scale priors for mean event
time; `parameter="median"` requires priors and thresholds in median-time units.

```python
from mdanderson_stats import arand_survival_posterior

survival = arand_calendar_replay(
    arrival_times=[0, 1, 2, 3], assignment_uniforms=[0.05, 0.95, 0.05, 0.95],
    prior=[[1, 1], [1, 1]], family="exponential",
    event_times=[[2, np.inf], [np.inf, 3], [4, np.inf], [np.inf, 2]],
    analysis_times=[2.5, 4.5], max_enrollment=4, max_duration=None,
    final_followup=4, minimum_enrollment=2, tuning=0,
    policy=policy,
)
expected = arand_survival_posterior(
    events=[2, 2], exposure=[6, 5], prior=[[1, 1], [1, 1]], tuning=0,
)
np.testing.assert_allclose(
    survival.looks[-1].posterior_probability, expected.best.probability,
)
assert survival.looks[-1].observed == 4
assert survival.decision_duration == 3
assert survival.completed_duration == 7
```

## Monitoring rules

Every arrival has an analysis immediately before assignment. Supplied
`analysis_times` add looks between arrivals. Observations due at a look's
timestamp are available at that look; future observations are excluded. Tied
arrivals retain their tape order. `same_time_order` controls whether a supplied
scheduled look at the same timestamp runs before or after those arrivals.

The initial equal-randomization period does not compute best-arm probabilities.
The replay defers posterior-based monitoring through that period. Once it
ends, allocation is proportional to best-arm probability raised to
`tuning`, followed by the selected floor rule. Zero tuning gives equal weights
over currently active arms. `maximize=False` prefers smaller response
probabilities or event-time parameters.

`minimum_enrollment` gates futility classification, loser suspension and early
stopping. After both this gate and the initial equal-randomization period:

- An arm is reversibly suspended when its best-arm probability is strictly
  below `loser_cutoff`. Subsequent looks can reactivate it.
- An active arm can win early when its best-arm probability is strictly above
  `early_winner_cutoff`.
- When maximizing, an arm becomes permanently futile if its posterior
  probability of exceeding `futility_threshold` is strictly below
  `futility_cutoff`. Futility is unavailable when minimizing.
- At final analysis, a nonfutile arm can win if its best-arm probability is
  strictly above `final_winner_cutoff`. Reversibly suspended arms remain
  eligible. There is no default winner if the cutoff is not met.

Omit an optional cutoff to disable that rule. Minimum enrollment is not a
minimum count of observed outcomes. Binary trials with incomplete final
follow-up have no final winner; the result reports that incompleteness.

## Required policy choices

| Policy | Meaning |
| --- | --- |
| `floor_transform` | `mixture` applies `(1-k*f)*w + f` to normalized active-arm weights and guarantees floor `f` when feasible. `clamp_renormalize` clamps then normalizes; its resulting weights can fall below `f`. |
| `ranking_scope` | `all_arms` retains permanently futile arms in best-arm comparisons; `nonfutile_arms` removes them. Suspended arms remain in comparisons under both choices so they can reactivate. |
| `trigger_order` | A permutation of futility, suspension and early-winner evaluation determines how simultaneous criteria are handled. |
| `duration_minimum_precedence` | `duration_wins` closes enrollment at the duration cap, including arrivals exactly at it. `minimum_enrollment_wins` can continue to the first accepted arrival reaching the minimum. |
| `multiple_winner` | Choose the eligible arm with the highest probability or the lowest zero-based index when multiple arms pass a cutoff. |
| `all_suspended_action` | Stop or skip candidate arrivals until a later analysis can reactivate an arm. Skipped candidates are not queued for later enrollment. Permanent futility remains distinct from temporary suspension. |
| `same_time_order` | Place supplemental scheduled analyses before or after arrivals at the same timestamp. Arrival-time pre-assignment analyses still occur. |

The guide does not resolve all these conventions. They are deliberately
documented Python choices, not recovered settings of the original executable.

## Trial limits and returned state

Supply a maximum enrollment, maximum duration, or both. `final_followup` runs
from the actual enrollment-close time. For a completed trial,
`decision_duration` is the enrollment-close time and `completed_duration` is
the final analysis time. An early-stopped trial reports its stop time for both,
without adding planned final follow-up. When minimum enrollment takes precedence
but the supplied tape ends before that minimum, the replay reports an incomplete
trial at the last processed time and does not invent a final winner.

The result contains immutable assignment and enrollment arrays, arm statuses,
winner decisions and compact analysis records. A record's counts and posterior
describe the state before its optional assignment. `assigned_patient` identifies
the original tape row. Attempted and blocked arrival counts describe candidates
processed before the terminal time; later candidates are not trial participants.

The implementation bounds tape sizes, retained looks and estimated work before
constructing full outcome/delay arrays. Its work bound includes repeated
patient scans as well as posterior comparisons. `max_work` can tighten that
bound; finite look and storage limits remain in force. Numerical tail failures
raise explicit errors before allocation. Terminal looks do not need allocation
weights. No parallel simulations or numerical workers are started.

The posterior kernels have 52 independent R reference comparisons. Calendar
checks cover delayed information, exact event-time availability, reversible
suspension, minimum-enrollment gates, strict cutoffs, terminal eligibility and
duration/follow-up limits. Native random streams, native control-order/floor
parity, multi-trial operating-characteristic reports and the full desktop
workflow remain open.
