# BOIN12 reference audit

The bounded fixtures in `tests/fixtures/boin12-*` are generated by
[`tools/reference_boin12.R`](../tools/reference_boin12.R). The runner uses the
CRAN `escalation` 0.2.3 implementation of the published BOIN12 algorithm in a
task-local R library. Downloaded source and app material remain under ignored
`research/raw/BOIN12/` and are not redistributed.

The `escalation` package declares GPL (>= 3). Its BOIN12 code identifies the

defaults and extensions; the package source is the executable numerical

## Statistical contract

The binary outcomes are toxicity `T` and efficacy `E`. With utilities
`u1=100` for `(T=0,E=1)`, `u2` for `(0,0)`, `u3` for `(1,1)`, and `u4=0` for
`(1,0)`, the quasi-beta-binomial calculation uses

```
x = (u1*y1 + u2*y2 + u3*y3 + u4*y4) / 100
Pr(u > ub | data) = 1 - BetaCDF(ub/100; alpha+x, beta+n-x)
```

where `ub = ubar + (100 - ubar)/2` and
`ubar = E[u]` under the specified toxicity and efficacy limits. A dose is
admissible when both `Pr(pT > phiT | data) < cT` and
`Pr(pE < phiE | data) < cE`. Defaults shown by the current app are
`phiT=.35`, `phiE=.25`, `cT=.95`, `cE=.90`, `u2=40`, `u3=60`, cohort size 3,
12 cohorts, starting dose 1, and stop-at-dose count 12.

`boin12-posterior.csv` records the quasi-beta posterior, both admissibility
tails, and the benchmark for unequal event patterns. `boin12-rds.csv` records
the rank-based desirability table for 0, 3, 6, and 9 patients. RDS ranks are
computed among admissible outcomes only; ties receive average ranks, so an RDS
can be fractional (for example 32.5).

## Dose decisions

The BOIN toxicity boundaries are calculated at `phiT`. At a current dose, the
published single-stage rule is:

* if the observed toxicity rate is at or below the escalation boundary, choose
  the admissible dose in `{d-1,d,d+1}` with highest desirability;
* if it is inside the stay interval and the current dose has at least `N*`
  patients, compare only `{d-1,d}`;
* if it is at or above the de-escalation boundary, move to `d-1` (bounded at
  dose 1);
* if no admissible dose remains, stop.

The extra exploration rule escalates to `d+1` when the current dose has at
least `K` patients, its observed toxicity is below the de-escalation boundary,
and the next higher dose has never been used. The app exposes `K` (default 9)
and the stopping threshold (default 12). The paper describes the equivalent
condition as more than eight patients. `boin12-decisions.csv` includes the
published example, an RDS comparison, extra exploration, de-escalation, an
empty start, and a non-default prior.

## Final OBD

The final procedure first applies one-dimensional isotonic regression (PAVA) to
the observed toxicity rates and chooses the MTD whose fitted rate is closest to
`phiT`, taking the highest dose on an exact tie. It then chooses the dose at or
below that MTD with the highest estimated utility. The OBD fixture preserves
the fitted toxicity vector, utility vector, admissibility indicators, MTD, and
OBD for the published example, a plateau-efficacy example, and a pooled
toxicity example.

## App/package scope and known differences

The current app includes extensions around the single-stage method: optional
3+3 run-in at `phiT=.25`, a two-stage toxicity-only-to-utility workflow,
user-selectable extra exploration, and a tradeoff utility mode. The runner
targets the published binary single-stage utility method. The `escalation`
implementation hard-codes its legacy extra exploration condition at `n > 8`
and does not implement the app's two-stage or 3+3 UI wrappers.

The source package's de-escalation branch returns the bounded lower dose without
rechecking admissibility; this is retained in the decision fixture as backend
behavior. Its internal implementation also uses an app-compatible high-dose
tie resolution in the desirability branch. These are implementation details to
verify explicitly rather than infer from a generic BOIN implementation.
